# Security Policy

## Reporting a Vulnerability

We take the security of Gitic seriously. If you find a security vulnerability, please do not disclose it publicly or file a public issue. Doing so puts the community and users at risk.

Instead, please report vulnerabilities using GitHub's built-in **Private Vulnerability Reporting** feature:

1. Navigate to the main page of the Gitic repository on GitHub.
2. Under the repository name, click the **Security** tab.
3. In the left sidebar, under "Reporting", click **Vulnerability reporting**.
4. Click **Report a vulnerability** to open the draft advisory form.
5. Fill out the form with a clear description, details on how to reproduce, and any impact.
6. Click **Submit report**.

Using Private Vulnerability Reporting allows you to securely collaborate with the project maintainers on a private draft advisory, test patches in a private fork, and publish a coordinated disclosure when a fix is ready, completely eliminating the need for unencrypted or external email communications.

## Supported Versions

Only the latest release of Gitic is actively supported with security updates. We recommend always running the latest version of the tool.

| Version | Supported          |
| ------- | ------------------ |
| v0.1.x  | :white_check_mark: |
| < v0.1  | :x:                |
